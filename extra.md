## Дополнительная информация

Здесь собрано то, что, возможно, было на лекциях, не вошло в темы экзамена, но может оказаться вопросом.

### Реализация `OneShot`

```cpp
#include <functional>
#include <mutex>

class OneShot {
public:
    void Call() {
        mutex_.lock();
        if (!called_) {
            called_ = true;
            func_();
        }
        mutex_.unlock();
    }

    bool IsCalled() {
        mutex_.lock();
        bool result = called_;
        mutex_.unlock();
        return result;
    }

private:
    std::mutex mutex_;
    bool called_ = false;
    std::function<void()> func_;
};
```

```cpp
auto os = std::make_shared<OneShot>(func);

// запускаем T1 с захваченным shared_ptr
std::thread t1([ptr=&os] {
    while (!os->IsCalled()) {}
});

// T2 вызывает Call()
os->Call();

// T2 выходит из области видимости
// os уничтожается -> вызывается деструктор OneShot -> вызывается деструктор Mutex
```

### Реализация LockFree аллокатора для очереди и стека

На самом деле оператор `new` вообще-то использует внутри себя мьютексы.

Идея решения проблемы с `new/delete` - написать `FreeListAllocator` - это аллокатор, который будет выделять нам ноды. Изначально у него много нод зарезервировано и есть связный список нод, которые он может дать нам следующими. Когда нам надо освободить ноду, мы её не удаляем, а вставляем в стек из свободных нод. Голова - ближайшая свободная нода, которую мы можем использовать. 

```cpp
class FreeList {
private:
    std::atomic<Node*> head_;

public:
    FreeList() : head_(nullptr) {}

    // Метод захвата узла из свободного списка.
    Node* acquire() {
        Node* old = head_.load();

        // Цикл будет продолжаться, пока есть элемент в списке и пока CAS не удастся.
        while (old != nullptr) {
            Node* next = old->next;        
            Node* desired = next;

            // Пытаемся атомарно заменить head_ с old на desired.
            if (head_.compare_exchange_weak(old, desired)) {
                // Успешно "вырвали" старую голову из списка.
                old->next = nullptr;
                return old;
            }
            // Если CAS не удался, значит другой поток изменил head_ раньше.
        }

        // Если дошли до сюда (old == nullptr), значит список был пуст.
        return new Node();
    }

    // Метод возврата узла обратно в свободный список.
    void release(Node* node) {
        Node* old = head_.load();

        for (;;) {
            node->next = old;
            Node* desired = node;

            // Пытаемся атомарно установить node в качестве новой головы.
            if (head_.compare_exchange_weak(old, desired)) {
                return;
            }
            // Если CAS не удался, значит другой поток изменил head_ за это время.
        }
    }

    // Деструктор — освобождает все узлы, которые остались в свободном списке.
    ~FreeList() {
        Node* cur = head_.load();
        Node* node = cur;

        // Проходим по всему списку, удаляя каждый узел.
        while (node) {
            Node* next = node->next;
            delete node;
            node = next;
        }
    }
};
```

### Разновидности `memory order`

| memory_order | `Load-Load` | `Load-Store` |` Store-Store` | `Store-Load` |
|--------------|-----------|------------|-------------|------------|
| `relaxed`      | ❌        | ❌         | ❌          | ❌         |
| `consume` (устарел) | ✅    | ✅         | ❌          | ❌         |
| `acquire`      | ✅        | ✅         | ❌          | ❌         |
| `release`      | ❌        | ✅         | ✅          | ❌         |
| `acq_rel`      | ✅        | ✅         | ✅          | ❌         |
| `seq_cst`      | ✅        | ✅         | ✅          | ✅         |

**Примечание:** `consume` помечен как устаревший, так как на практике его поддержка ограничена, и компиляторы часто заменяют его на `acquire`.

#### Расшифровки

* `Relaxed` - нет никаких барьеров, гарантирует только атомарность операции

* `Consume` - барьер для зависимости данных (если загрузка A, то любой доступ, зависящий от A, не может быть переупорядочен)

* `Acquire` - барьер чтения (запрещает переупорядочивание последующих операций перед текущей загрузкой)
Запрещает:
    * **Load → Load** (чтение после не может быть раньше чтения до)
    * **Load → Store** (запись после не может быть раньше чтения до)

* `Release` - барьер записи (запрещает переупорядочивание предыдущих операций после текущей записи)
Запрещает:
    * **Load → Store** (чтение до не может быть после записи после)
    * **Store → Store** (запись до не может быть после записи после)

* `Acq_rel` - комбинация `Acquire` и `Release`

* `Seq_cst` - устанавливает все барьеры (все операции с `seq_cst` во всей программе следуют одному глобальному порядку)
