## Условные переменные: std::condition_variable. Семафоры, класс std::counting_semaphore. Реализация семафора через condition_variable.

### `std::condition_variable` — зачем она нужна

Мьютекс решает проблему взаимного исключения, но не решает задачу ожидания события. 
Например, поток-потребитель хочет ждать, пока в очереди появятся данные. Наивный подход — активное ожидание (busy wait):

```cpp
while (queue.empty()) { /* крутимся вхолостую */ }
```

Это расходует $100\%$ CPU впустую. `std::condition_variable` позволяет
потоку заснуть (освободив мьютекс) и проснуться ровно тогда, когда условие выполнено.

### Интерфейс `std::condition_variable`

`std::condition_variable` работает только в паре с `std::unique_lock<std::mutex>`.

| Метод                   | Что делает                                                                |
|-------------------------|---------------------------------------------------------------------------|
| `wait(lock)`            | Атомарно освобождает мьютекс и блокирует поток                            |
| `wait(lock, predicate)` | То же, но при пробуждении проверяет условие (защита от `spurious wakeup`) |
| `notify_one()`          | 	Будит один из ожидающих потоков                                          |
| `notify_all()`          | 	Будит все ожидающие потоки                                               |

### Проблема spurious wakeup

Поток может проснуться без вызова `notify` — это называется ложным пробуждением (`spurious wakeup`). 
Поэтому всегда проверяйте условие после пробуждения. Версия `wait(lock, pred)` делает это автоматически: 
она эквивалентна `while (!pred()) cv.wait(lock);`.

### Очередь производитель–потребитель

```cpp
#include <mutex>
#include <condition_variable>
#include <queue>

std::mutex mtx;
std::condition_variable cv;
std::queue<int> data_queue;

// Производитель
void producer() {
    for (int i = 0; i < 10; ++i) {
        {
            std::unique_lock lock(mtx);
            data_queue.push(i);
        }
        cv.notify_one();  // будим одного потребителя
    }
}

// Потребитель
void consumer() {
    while (true) {
        std::unique_lock lock(mtx);
        // Ждём, пока очередь не пуста (защита от spurious wakeup)
        cv.wait(lock, [] { return !data_queue.empty(); });

        int val = data_queue.front();
        data_queue.pop();
        lock.unlock();

        process(val);
    }
}
```

Когда потребитель вызывает `cv.wait(lock, pred)`, происходит следующее:
1) Проверяет предикат — если `true`, продолжает работу
2) Если `false` — атомарно освобождает `lock` и засыпает
3) После `notify_one()` просыпается, снова захватывает `lock`, проверяет предикат
4) Если предикат теперь `true` — продолжает, иначе засыпает снова

### Семафоры

**Семафор** — примитив синхронизации с целочисленным счётчиком. В отличие от мьютекса, семафор не имеет понятия «владельца»: 
один поток может сделать `release()`, а другой — `acquire()`.

* `acquire()` — уменьшает счётчик на 1; если счётчик = 0, поток блокируется
* `release()` — увеличивает счётчик на 1 и будит один заблокированный поток

**Мьютекс** — это бинарный семафор (счётчик 0 или 1) с добавленным понятием владельца.

### `std::counting_semaphore` (C++20)

```cpp
#include <semaphore>

// Шаблонный параметр — максимальное значение счётчика
// Аргумент конструктора — начальное значение
std::counting_semaphore<5> sem(5); // разрешаем до 5 одновременных потоков

void worker() {
    sem.acquire();   // войти в секцию (счётчик--)
    // ... критическая секция ...
    sem.release();   // выйти (счётчик++)
}
```

`std::binary_semaphore` — это алиас `std::counting_semaphore<1>`. Типичное применение — ограничение числа одновременных подключений к БД, пулу потоков и т.п.

### Реализация семафора через `condition_variable`

Ключевое отличие семафора от мьютекса — разделение `acquire` и `release` между разными потоками. 
Это делает семафор удобным для сигнализации: один поток сигналит (`release`), другой ждёт (`acquire`),
что невозможно с мьютексом.
